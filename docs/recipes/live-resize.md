# Живой ресайз

**Применимость:** любое приложение на gpui, Windows.

**Проблема.** При перетаскивании края окна содержимое отстаёт от рамки, в новой области — чёрная полоса,
«будто очень низкая частота кадров». Пока пользователь тянет край, Windows крутит модальный цикл; кадр
нового размера gpui рисовал по таймеру цикла (~15,6 мс) или по `WM_PAINT`, который мышь откладывает.
Через DirectComposition картинка не растягивается до нового размера окна; у swapchain окна с
`DXGI_SCALING_NONE` новая область чёрная.

**Решение** (как у wgpu и eframe в Урфине):
1. Внутри цикла перетаскивания (`WM_ENTERSIZEMOVE` … `WM_EXITSIZEMOVE`) рисовать кадр прямо на `WM_SIZE`.
   Вне цикла нельзя: `WM_SIZE` от `Window::resize` из кода приложения приходит, когда приложение занято.
2. Swapchain окна (`CreateSwapChainForHwnd`) с `DXGI_SCALING_STRETCH`: пока кадра нет, DWM растягивает прошлый.
3. DirectComposition выключена по умолчанию; нужна только для прозрачного или размытого фона (Mica за
   содержимым невозможна — учитывать в дизайне).

**Проверка.** Глазами — тянуть край и угол (автоматизация потребовала бы двигать курсор). Регрессии —
`resize-check.ps1` (разворачивание, сворачивание, `SetWindowPos`, доля чёрных пикселей; режим «с экрана»
показывает то, что видит пользователь) и бенч.
