# Кадры по запросу

**Применимость:** любое приложение на gpui, Windows.

**Проблема.** Windows-платформа gpui будила все окна на каждом обновлении экрана (поток `VSyncProvider`
→ `RedrawWindow`): 144–180 пробуждений в секунду, ~3 % CPU в простое, хотя кадр не нужен.

**Решение.** Ядро gpui уже сообщает о нужде в кадре (`PlatformWindow::frame_waker`, `schedule_frame`).
Окно держит флаг «нужен кадр»; поток vsync спит на условной переменной, пока флага нет, и раз в
секунду просыпается проверить устройство и остановку. Отложенный повторный кадр (`draw_window` во время
отрисовки) тоже ставит флаг.

**Результат.** Простой 3,0 → 0,0 %, пробуждения потока vsync 158 → 1–3 в секунду (Intel, 144 Гц).

**Откуда.** Postman S1-02, патч `third_party/gpui-pre-windows` (`vsync.rs`, `platform.rs`, `window.rs`,
`events.rs`); теперь — `crates/pets-gpui-windows`.
