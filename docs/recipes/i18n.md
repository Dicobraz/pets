# Тексты интерфейса: Fluent, RU + EN

**Применимость:** любое приложение Pets (крейт `pets-i18n`).

**Проблема.** Строки интерфейса расползаются по коду: часть переведена, часть зашита по-русски, в одном
языке ключ есть, в другом нет, у перевода другие переменные — и это видно только глазами в работающем
приложении. Библиотеки (`pets-ui`) тоже показывают текст, а языки приложения и библиотек должны
переключаться вместе и на лету.

**Решение.**
- Тексты — Fluent (`.ftl`), по файлу на язык, вшиты `include_str!`: набор `&[Resource]` = `&[("ru", …), ("en", …)]`.
  Свой набор у приложения и у каждой библиотеки; приложение собирает всё вместе:
  `pets_i18n::init(&[APP_FTL, pets_ui::FTL], &settings.lang)` (`"auto"` — язык ОС).
- В коде — только ключи: `tr!("mail-reply")`, `tr!("files", n = 3)`. Нет ключа в языке — текст из EN,
  нет и там — сам ключ (видно сразу). Плюрали — по языку сообщения (`[one]`/`[few]`/`*[many]` в RU).
- Смена языка — `set_language("en")`: ресурсы те же, снимок `I18n` подменяется целиком. Кэши текста
  сравнивают свой номер с `epoch()`.
- Тест приложения на сырые строки: `raw_strings(include_str!("main.rs"))` по каждому файлу интерфейса —
  строковые литералы с кириллицей вне комментариев. Тесты в конце файла (после `#[cfg(test)]`) не
  сканируются; осознанное исключение — `// i18n-ok` в той же строке.
- Тест приложения на наборы: `assert_eq!(pets_i18n::check(&[APP_FTL, pets_ui::FTL]), [])` — ошибки разбора,
  ключ только в одном языке, дубль ключа, разные `$переменные` у ключа в разных языках.
- Ловушка: Fluent по умолчанию обрамляет подстановки знаками изоляции U+2068/U+2069, шрифты gpui рисуют
  их квадратиками. В крейте `set_use_isolating(false)` уже включён — свои бандлы так же.

**Откуда.** Идея — `urfin-i18n` в Урфине (глобальный `RwLock<Arc<I18n>>`, `epoch`, `tr!`); переписано заново
для Pets: без чтения файлов с диска, наборы библиотек, проверки `check` и `raw_strings` для тестов
приложений. Первый потребитель — Postman.
